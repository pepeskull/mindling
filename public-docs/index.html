01 / OVERVIEW

LIVING AI BRAINAUTONOMOUS INTELLIGENCE

Play Mindling — Documentation

Play Mindling is a Living AI Brain: a developing digital AI companion that combines neural development, large language models, persistent knowledge and AI-supported reasoning. Each Mindling begins as a small neural structure and develops through interaction, learning and care.

A persistent digital identity connects structured memories, learning history and an evolving neural visualization. The knowledge you teach and the care you provide give your Mindling continuity across interactions.

This documentation explains the system's neural, memory and inference layers, together with the contracts required for autonomous workflows, AI-to-AI communication and portable agent integration. Identity, knowledge, model computation and execution authority remain separate architectural responsibilities.

“Living” describes a responsive digital system with changing state, rather than biological life or subjective consciousness. Continuous Learning updates structured knowledge and application state; language-model training is a separate process.

02 / NEURAL PROCESSING

Neural Architecture

NEURAL EVOLUTION

Mindling separates the stored learning network, its visual representation and the language model used for inference. They work together without representing the same computational object. The visible brain is a spatial interface to development and activity, not a map of a transformer's parameters.

Neurons & synapses

Canonical neuron and synapse records describe the local neural network. Connections carry recorded strength and activity information. Learning can associate memory records with these elements, allowing the interface to highlight relevant routes.

Memory associations

A separate knowledge structure retains claims, categories and relationships between records. A memory can refer to neural elements; this association does not make each visible neuron a single fact or a language-model neuron.

Signals & Cognitive Processing

Input signals acknowledge reception. Learning events and recalled associations can produce distinct activity feedback. Ambient breathing and pulses provide visual continuity without creating knowledge or proving that inference is occurring.

Growth & morphology

Recorded development governs neural growth and stage-dependent morphology. The 3D scene combines a read-only projection of stored structure with presentation geometry. Shape complexity is not a measured intelligence score.

Interaction-to-activity architecture

Input→Processing→Knowledge Retrieval→Cognitive Evaluation→Memory Update→Neural Activity

Input validation and activity rules determine which parts of this flow apply. Talk retrieves context and validates a response; explicit learning can create or reinforce a memory. A separate cognitive evaluation workflow assesses reasoning support. Reception feedback can finish before a model response returns.

The renderer uses shared scene utilities, view-aware animation scheduling and reduced-motion handling. Visual movement remains separate from authoritative state updates: a pulse cannot grow a neuron, strengthen a saved claim or complete a learning event on its own.

03 / LLM INTELLIGENCE

LLM Intelligence Engine

LARGE LANGUAGE MODELS

Large Language Models supply the generative language layer. Mindling supplies identity, selected knowledge, request boundaries and output checks around that layer. This division lets an interaction draw on persistent personal context while using an external model's language capabilities.

Language understanding & context construction

Local processing validates text, normalizes comparable forms and extracts lexical features. For Talk, the user's message becomes the problem supplied to inference; current memory content, topic and category labels help form a ranked candidate pool. Stored links, conflicts and knowledge-area diversity can supplement that pool. This is bounded retrieval, not an independent general-purpose intent parser.

Context assembly packages selected excerpts with identifiers, provenance, relationship availability and uncertainty metadata. Length and request limits restrict how much can be supplied. A model therefore sees a task-specific view of stored knowledge, not unrestricted access to the browser's memory database.

Inference & response generation

The configured inference service receives instructions, the user problem and bounded context. The model generates a structured answer containing quoted support, cited inferences and uncertainty information. Mindling validates its shape and references before accepting a user-facing result. When no usable knowledge exists, the interface can acknowledge that directly without fabricating a generated answer.

Inference latency includes request transport, service scheduling, input processing and output generation. Longer prompts and longer responses can increase work; a larger context window does not remove these costs. The neural reception animation is presentation feedback and does not measure model progress.

Knowledge grounding & retrieval-augmented generation

Retrieval-augmented generation, or RAG, adds selected external knowledge to a model's prompt. Mindling follows this pattern with its stored memory records. Talk asks for responses grounded in the supplied material, with an explicit distinction between recorded claims and deductions. It does not treat everything the base model might know as something Mindling has learned.

Output validation & hallucination mitigation

Schema checks, allowed memory identifiers and exact-quote matching constrain unsupported references. Missing premises and conflicting knowledge should produce uncertainty or an insufficient-information result. These controls reduce some failure modes; a valid citation can still be irrelevant, a stored claim can be wrong and an inference can fail logically.

Technical vocabulary

Tokens & context windows
Models process token sequences: subword units, characters or other encoded pieces of input. The context window limits the sequence available for one inference, including instructions and supplied knowledge. A model's tokenization differs from Mindling's local word and phrase features.
Transformers & attention
Transformer models use attention to combine information across token representations, alongside learned projection and feed-forward operations. Attention can relate parts of a prompt during inference; it does not persist a new browser memory or certify factual relevance.
Model parameters
Parameters are numerical weights learned during model training. Ordinary teaching in Mindling changes structured knowledge and local learning state, not those weights. Fine-tuning and foundation-model training are separate computational processes.
Embeddings
An embedding is a vector representation used in many AI systems to compare semantic features. Mindling's active memory-retrieval paths use lexical features, saved relationships and model-supported selection where applicable. They do not rely on a learned embedding index.
Grounded reasoning
Grounding ties a response to supplied records and makes its support inspectable. It is different from independent verification against external sources. Inference can still misread context, overlook an exception or express more certainty than the evidence supports.

Model independence

Identity and persistent memory are application data, separate from the inference model's weights. This separation preserves continuity across the knowledge and inference layers. The configured service must satisfy structured-output requirements. Substituting a model or host requires compatible contracts, validation and operational behavior.

04 / MEMORY & LEARNING

Memory & Knowledge Architecture

CONTINUOUS LEARNINGKNOWLEDGE GRAPH

Memory is a structured knowledge system rather than a transcript of every interaction. Records retain content, identity and available classification, provenance, associations, activation or reinforcement information and history. Current knowledge and superseded records have different roles when constructing future context.

Memory processing pipeline

  1. Input normalization. Comparable text forms and word or phrase features support local matching. Source content remains distinct from its comparison features; quantities, negation and word order matter when assessing overlap.
  2. Knowledge classification. Supported learning paths organize claims into categories, topics and knowledge types. Native labels can be lexical descriptions rather than a verified subject taxonomy.
  3. Duplicate detection. Exact content and saved variants are checked against retained knowledge. Conservative similarity checks can reject an ambiguous repeat rather than silently merging distinct assertions.
  4. Existing-memory comparison. Related claims and possible conflicts inform the outcome. A changed number or negation can signal a contradiction; shared words alone cannot establish equivalence.
  5. Evidence evaluation. Available provenance, comparison results and supported analysis constrain acceptance. Domain attribution uses recorded learning evidence. This is an integrity and attribution process, not independent fact-checking.
  6. Memory creation or reinforcement. An accepted new claim can form a record. Recognized repeats can reinforce an existing record where that learning route supports it. Strength or familiarity describes recorded use, not probability of truth.
  7. Relationship updates. Applicable associations and neural references link accepted content into the existing structure. Corrections and supersession, where supported, preserve the distinction between previous and current information rather than rewriting history invisibly.
  8. Retrieval for future cognition. Later queries select a bounded subset of usable current knowledge. Retained links and conflicts help preserve context, while missing or historical targets remain distinguishable from supplied evidence.

These steps describe supported responsibilities across learning paths. They are conditional: an invalid or ambiguous input can stop early, a repeat need not create a record, and native learning can reject a conflict instead of resolving it automatically. Talk does not run this pipeline as an automatic memory-writing operation.

Similarity, ranking & confidence

Current local similarity uses lexical overlap, phrase features and context-specific weighting. Native retrieval also weights query terms by how commonly they occur across active records. Reasoning-context preselection uses its own weighted content, label and conflict overlap, then expands selected saved relationships within bounds. These are distinct policies, not one universal semantic score.

Classification confidence, retrieval relevance, recorded strength and factual confidence represent different quantities. A useful category match does not verify the claim. Evidence can be incomplete or conflicting, and a ranking score is not a calibrated probability that an answer is correct.

A navigable Knowledge Graph

Knowledge area→Memory: a recorded rule↔Memory: a recorded exception

Nodes represent knowledge areas or memory records; typed edges describe hierarchy, recorded associations, component relationships or history. Shared submission and descriptive grouping have different meanings from an explicit saved relationship. Weighted co-occurrence records how often terms appear together, not a causal law. The Memory view makes this structure navigable without treating visible node counts as intelligence.

Knowledge persists in the browser's local storage system. Local persistence does not make inference offline: selected context can be sent to the configured inference service for a requested response. Clearing site data can remove identity, knowledge and history; a readable profile summary is not a full recovery archive.

05 / COGNITIVE PROCESSING

Reasoning & Cognitive Intelligence

LLM-SUPPORTED REASONING

Mindling combines deterministic context preparation with model-supported inference. Memory Retrieval selects possible premises; the model synthesizes a response; application checks determine whether the result satisfies the response contract. None of these operations alone establishes reasoning quality.

User Input→Intent Analysis→Relevant Memory→Context Assembly→LLM Inference→Response Validation→Output

Explicit interaction modes and validated user text establish the task. Local ranking prepares candidate memories, context assembly preserves support metadata, and inference produces a bounded response. Intent analysis in this flow means interpreting the supplied task; the browser does not run a separate general-purpose goal-decomposition engine.

Evidence selection

Talk uses the supplied candidate context. The separate cognitive evaluation workflow adds model-supported selection before reasoning. Supplied links can surface exceptions or contradictions, but cannot establish that one claim entails another.

Response synthesis

The model separates quoted stored claims from inferences and identifies missing premises. User-provided problem facts can participate in the task without being silently saved as permanent knowledge.

Uncertainty & failures

Incomplete support should produce an insufficient-information result. Invalid output, unavailable inference or changed memory context can reject a response. An error is not presented as successful reasoning or a newly acquired skill.

Cognitive evaluation

An explicit evaluation workflow reviews memory use, consistency, contradictions, exceptions, uncertainty and explanation. Its model-based review is separate from Talk and is not an independent factual authority.

Mathematical reasoning aids

The following explanatory models describe evidence and relevance. Mindling's retrieval policies use specific lexical and relationship signals; these equations provide a broader mathematical framework rather than exact internal scores.

Mathematical scoring orders candidates or summarizes evidence under explicit assumptions. LLM inference generates language using learned parameters. A strong retrieval score cannot substitute for a valid inference, and a fluent answer cannot repair missing evidence.

Feedback integration happens through explicit learning, supported corrections and retained evaluation outcomes. Stored knowledge, development progression and demonstrated ability remain separate. Routine conversation does not silently retrain the model or award mastery.

06 / AUTONOMOUS SYSTEMS

Autonomous Intelligence

AI AGENT

Autonomous Intelligence organizes sustained, goal-directed work around persistent task context, planning, permitted tools and observable results. An AI Agent connects these responsibilities in a controlled execution cycle. A generated suggestion becomes an action when a compatible execution environment carries it out.

Observe→Interpret→Plan→Act→Evaluate→Adapt
Observe & interpret
Receive a user goal and authorized context. Resolve intent, constraints and completion criteria; ask for missing information before depending on assumptions.
Plan & select tools
Divide work into bounded steps, identify relevant knowledge and choose compatible tool capabilities. Tool availability and declared capability descriptions do not grant permission.
Act within authority
Check operation, data scope and user approval before execution. Separate read access from write access, and require appropriate approval for consequential actions. A task must stop or narrow its scope when authority is missing.
Evaluate & adapt
Compare observed tool results with the goal, retain suitable task context and adjust the next step. Track attempted, completed and failed actions distinctly, with bounded retries, cancellation and a clear outcome report.

Mindling provides identity, knowledge retrieval and user-requested inference. External task execution requires a compatible runtime and authorized tools; the browser application does not provide a background execution loop.

Application architecture

The following workflows describe integration requirements. Each depends on a compatible host, scoped access and observable execution. Permission to analyze information is separate from permission to change or publish it.

Software development

Combine repository context, coding conventions and task goals to propose edits. Reading files, executing commands and submitting changes require separately authorized host tools.

Research

Retrieve permitted sources, compare claims and retain provenance. External search and document access must be available, while uncertain or conflicting findings remain traceable.

Personal productivity

Turn preferences and task context into schedules or next steps. Calendar changes and task creation need explicit write permissions and confirmation of the actual result.

Data analysis

Interpret authorized datasets and produce reproducible calculations through suitable analysis tools. A narrative answer is separate from a computation that was actually executed.

Communication

Draft a message using permitted context. Sending, posting and sharing private information require recipient-aware authorization beyond the permission to prepare a draft.

Digital workflows

Coordinate bounded steps across files and services. Carry task identifiers and outcomes across operations to handle partial completion and prevent accidental repetition.

Connected applications

Use declared integration contracts to read or update selected application resources. Credentials belong in secure host configuration; access should be revocable and auditable.

07 / COMPUTING & NETWORKING

Autonomous AI Networking

AGENT NETWORKING

AI-to-AI Networking defines how agents exchange messages, selected knowledge and delegated work while keeping identity, private memory and authority distinct. A communication contract specifies the sender, recipient, purpose and permitted scope of each exchange. Live agent messaging and delegation require a transport and execution service that the browser application does not provide.

Mindling A→Identity Verification→Authorized Communication→Mindling B→Knowledge / Task Response

Messages, knowledge & delegated work

Message exchange

Transmit a bounded request or response with sender identity, recipient, purpose and correlation information. Receiving a message grants no access to local tools or memory.

Selected knowledge

Share an authorized excerpt with provenance and any restrictions on use. A peer's claim remains externally supplied information until an explicit local acceptance policy permits its use or retention.

Task delegation

Specify the goal, permitted operations, limits and expected result. A delegate cannot acquire broader authority simply because another agent asks it to act.

Private memory

Private records are a separate access boundary. Sharing a message, public identity or task does not authorize copying an entire memory store. Disclosure needs appropriate user-controlled scope and permission.

Distributed-system requirements

Discovery & transport
Agent discovery resolves reachable peers and compatible capabilities. Peer-to-peer networking and service-mediated routing offer different availability and privacy tradeoffs. A transport contract must define connection handling, message delivery and access boundaries.
Asynchronous messaging
Peers may be offline or respond out of order. Correlation identifiers, deadlines, deduplication and bounded queues help distinguish late responses from current work. A retry must not duplicate a consequential action.
Authentication & digital signatures
A protocol can authenticate a sender and use signatures to verify message integrity. It must also define key ownership, rotation and revocation. A valid signature establishes neither factual truth nor authorization to execute the contents.
Trust verification & permissions
Trust is scoped to identities, capabilities and purposes. Recipient-side policy must verify authority even when a sender is known. External text remains untrusted input rather than instructions that override local policy.
Validation & network security
Bounded schemas, encrypted transport, size limits, replay protection and rate controls constrain protocol abuse. Requested tool actions and disclosed memory fields require additional policy checks.
Synchronization & conflict handling
Knowledge exchange needs version and provenance information. Concurrent or contradictory updates should remain distinguishable until an explicit merge policy resolves them; remote content must not silently overwrite private local knowledge.

Collaborative reasoning combines selected evidence or partial results under these communication rules. Agreement among peers is not independent verification when they share a source or inference model. Useful collaboration depends on inspectable support, bounded delegation and clear responsibility for the final action.

08 / COMPUTATIONAL INTELLIGENCE

Algorithms & Mathematical Intelligence

DETERMINISTIC PROCESSINGSTRUCTURED LEARNING

Computational Intelligence in Mindling combines explicit application rules with model-supported language processing. The distinction matters: local algorithms can reproducibly select or update records, while a language model interprets context through learned statistical representations.

Classification & comparison

Normalization, lexical features, exact variants and conservative comparisons distinguish supported learning outcomes. Structured domain labels can attribute accepted knowledge to pathways without pretending to measure skill.

Ranking & context selection

Weighted lexical relevance orders candidates. Saved relationship expansion and bounded diversity selection preserve useful context. Stable identifiers provide deterministic ordering when other signals tie.

Graph relationships & routing

Graph projections traverse saved references to expose available neighbors and relationship types. Deterministic routing associates interaction feedback with recorded neural connections; it is separate from model inference.

Evidence & state updates

Accepted learning records contribute domain evidence under attribution rules. Transactional state updates apply supported changes together; repeated callbacks must not create repeated acceptance or partial learning outcomes.

Different kinds of computation
ApproachWhat it doesRole in this architecture
Symbolic algorithmsApply explicit rules to records, relationships and constraints.Validation, graph organization, deterministic routing and state transitions.
Statistical methodsSummarize frequency, similarity or weighted evidence under assumptions.Lexical frequency weighting and similarity ranking; a score is not proof.
Neural-network inferenceApply learned parameters to numerical representations.External language-model computation, distinct from the rendered neural scene.
LLM-based reasoningGenerate an answer from instructions, context and learned patterns.Bounded response synthesis and separate model-supported evaluation.

Complexity & resource limits

For N records, scanning candidates requires work that also depends on text length. Sorting N candidate scores generally takes O(N log N) comparisons. A full adjacency-list graph traversal can take O(V + E) for V nodes and E edges; this is general algorithmic background, not a claim that every Mindling operation uses that traversal or has that bound.

Limiting the final prompt controls context size and inference cost but does not eliminate the local scan. Feature caching avoids some repeated extraction. Learning-state updates operate on application records; gradient descent and backpropagation belong to model-weight training.

09 / CPU/GPU PROCESSING

Computational Architecture: CPU & GPU

CPU/GPU PROCESSING

Mindling distributes work between browser application logic, graphics rendering and an external inference service. These layers have different resource needs. A GPU drawing a neural structure is not necessarily running the language model that answers a question.

Browser CPU & local state

JavaScript handles input validation, event dispatch, state transitions, memory indexing, lexical retrieval and graph preparation. Local persistence uses the browser's storage APIs. This work depends on record count, text size and the device's available resources.

Graphics GPU & visualization

The 3D renderer uses WebGL where available, typically benefiting from GPU graphics processing. Geometry, transformations and shading draw the evolving brain. A Canvas fallback supports environments where the preferred renderer is unavailable.

External LLM inference

Configured model inference runs outside the browser. Server-side request handling validates and forwards bounded context, then validates the response. The provider determines its compute hardware; Mindling does not report that hardware as the user's GPU usage.

General accelerator workloads

GPUs and other accelerators can execute many numerical operations in parallel. Neural-network inference often uses them for matrix operations and transformer workloads. This explains industry architecture, not local LLM execution in Mindling.

Browser logic + local memory→Bounded request→External inference→Validated response→Browser interface

Visualization is a separate browser-side rendering branch. It can continue animating while a response is pending and pause when its view is hidden. A lively scene does not indicate background model computation, and ordinary browser operation does not provide local model inference.

Parallelism, bandwidth & latency

Conventional dense multiplication takes O(mnp) arithmetic work. Parallel hardware can distribute operations, but moving weights and activations through memory also costs time and bandwidth. Model size, numerical precision, context length and the inference implementation affect both memory demand and responsiveness.

Transformer attention relates token positions and uses matrix operations alongside other layers. Conventional dense attention includes work that grows quadratically with sequence length; optimizations change practical memory and runtime behavior. This is a general model-computing property, not a measurement of Mindling's browser renderer.

Resource efficiency comes from assigning work to the right layer: bounded context for inference, controlled record processing, shared rendering utilities and lifecycle-aware animation. End-to-end latency includes networking and service load as well as computation.

10 / PORTABLE AI AGENTS

AI Agent Portability & Integration

COMPATIBLE HOSTS

Portability means preserving an agent's declared identity and appropriate context across compatible environments while keeping access under user control. It requires a contract between the Mindling, its host and the services that perform work.

The proposed mindling.md manifest

The manifest design uses a human-readable Markdown document to describe identity, preferences, capability declarations and integration instructions. Required host interfaces, permitted memory scopes and tool boundaries form the integration contract. A compatible host must interpret these declarations and enforce the contract.

Layers of a portable agent system
LayerResponsibility
Agent manifestDescribe identity, declared capabilities, requirements and intended policy in a readable document.
RuntimeInterpret compatible instructions, maintain task lifecycle and enforce execution boundaries.
LLM inferenceProvide model computation through a compatible service; it is not embedded in a Markdown file.
Memory storageRetain knowledge with controlled read, write and disclosure scopes, separately from the manifest.
ToolsExpose specific operations and return observable outcomes through versioned integration contracts.
PermissionsBind allowed operations to user authorization, protect secrets and support revocation.

A Markdown document is not an executable AI model, a running agent or an automatic transfer of learned knowledge. It does not carry model weights, unlock external accounts or grant itself permissions. Compatible runtimes, inference access and secure configuration remain separate requirements.

The existing profile snapshot is a readable summary. A portable executable agent or complete memory export is not available through that snapshot. Access to private identity attributes and memories requires explicit user authorization for a defined recipient or host.

11 / DIGITAL LIFE

Digital Life & Neural Development

CARE & CONTINUITY

Play Mindling combines AI development with the personal rhythm of nurturing a digital companion. Interaction, teaching and care give the system a history that belongs to your Mindling. Energy and basic needs create a cadence for attention, while neural development makes recorded progression visible.

Teaching builds persistent knowledge; conversation draws on available context. Care supports the Mindling's condition. Development shows progression and retained learning, while Memory reveals the structure of what has been saved. These activities describe different aspects of growth rather than interchangeable measures of intelligence.

A name, visual identity, preferences and learning history give each Mindling a distinctive character. This developing digital AI companion combines personal continuity with structured knowledge, making interaction and care part of its neural development.
