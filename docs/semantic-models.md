# Local semantic model attribution

Mindling runs semantic inference in the browser with Transformers.js 3.8.1 (Apache-2.0). The runtime is loaded as a pinned native module from jsDelivr; model files are fetched from Hugging Face only on first acquisition and cached by Transformers.js in the browser Cache API. User text is passed only to local model sessions and is never sent to an inference API.

* **Embedding:** `Xenova/all-MiniLM-L6-v2` (`main`), a Transformers.js ONNX conversion of `sentence-transformers/all-MiniLM-L6-v2`, Apache-2.0. It produces normalized 384-dimensional sentence embeddings. The quantized weights are approximately 23 MB, plus tokenizer/configuration files.
* **Pair decision:** `Xenova/nli-deberta-v3-xsmall` (`main`), a Transformers.js ONNX conversion of `cross-encoder/nli-deberta-v3-xsmall`, Apache-2.0. It produces contradiction, entailment, and neutral evidence for a sentence pair. The selected int8 graph is approximately 90.4 MB, plus tokenizer/configuration files.

The first semantic operation requires network access to acquire uncached runtime/model assets. Cached operation can work offline when the browser retains HTTP/Cache API entries, but this application does not install a service worker and therefore does not promise offline availability before or after cache eviction. The embedding model attempts WebGPU when exposed by the browser and falls back to WASM if initialization fails; the pair classifier uses WASM for broad compatibility. No server inference is used.

Embeddings are stored per memory as structured-cloneable `Float32Array` values in the existing IndexedDB `memories` store. At 384 float32 values, the vector payload is 1,536 bytes per memory before record overhead.

## Development calibration

On `localhost`, or when the page is opened with `?semantic-debug=1`, a read-only diagnostic is available as `window.__MINDLING_SEMANTIC_DEBUG__`. `compare(left, right)` returns cosine similarity, both directional NLI probability sets, mutual-entailment evidence, a decision reason, and the final classification. `runMatrix()` runs the complete 19-pair acceptance matrix against the production models; `runGeneralization()` covers reordered clauses, polarity, quantity, entities, time, causality, preferences, capability, obligation, uncertainty, conditionals, and role reversal. These examples are diagnostics only and are never consulted by runtime decisions. None of the methods mutate Mindling state or send text to an inference service.

`inspectEmbeddings(left, right)` reports dimensions, L2 norms, the first 12 values, byte-value identity, backing-buffer identity, and cosine similarity. Encoder and NLI calls are serialized independently because browser ONNX execution providers may reuse session output buffers. Every 384-value embedding is copied before the next encoder invocation begins.

The pair model's checked configuration maps output index `0` to `contradiction`, `1` to `entailment`, and `2` to `neutral`. Runtime initialization validates these names and fails truthfully instead of guessing an order. The embedding pipeline uses the complete input, tokenizer-provided attention mask, model-specific mean pooling, and post-pooling normalization through the Transformers.js feature-extraction pipeline. Mindling has no separate text-to-vector cache: persisted embeddings belong to complete canonical memory records in IndexedDB.

## Equivalence model investigation

`Xenova/paraphrase-MiniLM-L3-v2` is available through `inspectEquivalence(left, right)` as a lazy, diagnostic-only candidate. Its Apache-2.0 upstream model has 17.4 million parameters, produces 384-dimensional vectors, and its int8 ONNX graph is approximately 17.4 MB. It uses serialized WASM inference and browser caching. It is not canonical authority because it is still a bi-encoder similarity model rather than a joint sentence-pair classifier, and it has not yet been measured against Mindling's 19-pair matrix in a real browser.

`cross-encoder/stsb-TinyBERT-L4` is the M3.2.4 joint-input diagnostic candidate. It is an Apache-2.0, 14.4-million-parameter, four-layer TinyBERT cross-encoder trained as a single-output regressor on STS-B. Both sentences enter one forward pass. Its documented output is a raw regression logit; the Sentence Transformers convention applies a sigmoid for the normalized 0–1 similarity score (and multiplies by five for the STS-B scale). The portable fp32 ONNX graph is approximately 57.4 MB. Mindling loads it lazily on WASM, serializes its session, exposes raw and transformed scores, and marks it `canonicalAuthority: false`. WebGPU compatibility is not claimed because it was not tested here.

Two joint-input alternatives were rejected for production pending measurements: `cross-encoder/stsb-distilroberta-base` is Apache-2.0 and predicts continuous sentence-pair similarity, but its available full ONNX graph is approximately 329 MB; `cross-encoder/quora-distilroberta-base` is an Apache-2.0, 82.1-million-parameter duplicate-question classifier, but its portable full graph is likewise approximately 329 MB and its roughly 82.8 MB quantizations are architecture-specific. Both impose an unjustified mobile download/memory cost and neither has demonstrated sensitivity to the semantic-role negatives required by Mindling. `xpmir/cross-encoder-MiniLM-L12-BCE` was also reviewed, but its license, stable browser-ready ONNX distribution, label semantics, and Mindling-matrix behavior could not all be verified; it was therefore not added.

The Chromium `powerPreference` warning on Windows and ONNX Runtime messages about shape nodes being assigned to CPU are expected execution-provider performance notices, not semantic failures. `runtimeInfo()` reports the encoder backend selected by Mindling. References to `inpage.js` do not occur in this repository and normally identify an injected browser-extension script; Mindling does not suppress them.

## Canonical consistency investigation

M3.2.4 real-browser results reject TinyBERT as canonical authority: role-reversed sale, chase, and call propositions scored as highly as (and sometimes higher than) their correct active/passive or lexical paraphrases. Its useful response to negation, quantities, dates, and locations does not repair that structural failure, and no scalar threshold separates the measured classes. No fifth runtime model was added in M3.2.5.

`inspectSemanticIdentity(left, right)` reports retrieval, both NLI directions, mutual entailment/margin, maximum neutral/contradiction evidence, the diagnostic paraphrase and STS layers, and the unchanged production relation. `runSemanticIdentityMatrix()` is the single collection command. It combines the preserved 19 regression pairs, 22 broad/unseen generalization pairs, and 21 clean-slate/triangle/role diagnostics. Each row reports retrieval eligibility separately from current NLI classification, paraphrase-bi-encoder similarity, and joint proposition-candidate output. This distinguishes a retrieval miss from a retrieved candidate rejected by classification.

The supplied browser evidence proves that `Learn how to trade` reached retrieval (cosine about 0.9069) before production returned `RELATED`; therefore that central fragmentation is classification-side. It does not include the raw directional NLI probabilities needed to identify which mutual-entailment condition failed. Likewise, the gameplay outcome alone cannot establish whether the active/passive sale pair was absent from retrieval or rejected after retrieval. The new identity matrix captures those values rather than guessing. Mutual entailment remains an investigation hypothesis, not a new production rule.

Future canonical clustering should compare more than the top candidate when bounded retrieval permits, consider both canonical content and bounded representative variants, and avoid treating a memory cluster as an unrestricted transitive chain. A semantic prototype may improve retrieval, but pair evidence should still be checked against more than one representative expression before membership is accepted. This bounded-representative/quorum approach could prevent semantic chain drift while retaining the original canonical text. Inconsistent evidence should preserve a separate related memory rather than merge clusters. These are design notes only; production Teach behavior and the current candidate limit of three are unchanged.

## M3.2.6 shadow identity architecture

Production remains frozen. Its current path retrieves at most three candidates above `0.42`, evaluates each with bidirectional NLI, and applies `decidePair()`. `SAME_MEANING` currently requires cosine `>= 0.68`, minimum directional entailment `>= 0.92`, minimum directional margin `>= 0.72`, and maximum neutral probability `<= 0.12`; contradiction `>= 0.62` is checked first. The first candidate classified as same is reused, otherwise the highest-cosine candidate's relation becomes the overall result. Related/conflicting candidates are persisted as relationships by the existing Brain Engine path.

The measured false negatives have exact, different causes. `Learn how to trade` versus `Learn to trade` was retrieved, but its mutual entailment of about `0.90161` falls below production's `0.92` requirement. The active/passive John/Mary pair has decisive mutual entailment and margin, but its cosine of about `0.6646` falls below production's `0.68` same-meaning requirement. The dog active/passive pair clears all four gates and therefore becomes `SAME_MEANING`. Conversely, the supplied should/need and should/have-to measurements can clear every production gate, explaining those false merges and proving that merely lowering a threshold is not a complete solution.

`canonical-identity.js` implements a non-authoritative shadow interpretation. It keeps retrieval, identity, and relationship separate; uses directional entailment, symmetry, neutral, and contradiction evidence; and returns `SAME`, `NOT_SAME`, or `UNCERTAIN`. The `0.90`/`0.75` confidence bands are conventional diagnostic confidence bands rather than production thresholds fitted per sentence. Similarity models can add a support reason but cannot select identity. Strong NLI contradiction produces identity `NOT_SAME`, while relationship remains explicitly `UNRESOLVED`: NLI contradiction is not automatically a persisted conflict relationship. The known modality counterexamples remain an honest limitation—existing models may still produce false `SAME` evidence—so this shadow must not become canonical authority based on these results.

Shadow candidate inspection still retrieves a bounded top three, then ranks only candidates independently supported as `SAME` by mutual NLI evidence. It chooses stronger mutual entailment before retrieval cosine, with retrieval rank as a deterministic final tie-breaker. This investigates candidate-order artifacts without scanning the database or mutating memory. Triangle diagnostics report inconsistency rather than applying transitive merges. A future cluster should require agreement across bounded representatives and preserve separate memories under unresolved evidence.

The one-command evaluation contains the preserved 62 comparisons, a separate 40-pair held-out set, two non-persistent ten-input clean-slate simulations, and triangle analysis. Development tracing can also return the exact candidates and selected memory from the most recent real production evaluation through `lastProductionTrace()`. No identity keys or private material are included.

## M3.3 canonical memory and derived knowledge

Production now uses the validated identity evidence architecture after bounded MiniLM retrieval. For each of at most three candidates it evaluates the canonical text and at most one recent variant with bidirectional DeBERTa NLI plus supporting paraphrase/STS evidence. Every bounded representative must return `SAME`; any `NOT_SAME`, `UNCERTAIN`, high neutral evidence, asymmetry, contradiction, or missing similarity support keeps the new input separate. Among safe matches, mutual entailment is ranked before retrieval cosine. Similarity alone never merges a memory, and NLI contradiction is no longer automatically persisted as a conflict relationship. Exact normalized duplicates still use their deterministic fast path.

Knowledge areas are derived on demand from persisted canonical memory embeddings; they are not stored as a second source of truth. Memories are processed in stable creation/ID order, and the current presentation is bounded to eight areas. Because none of the local models generates reliable arbitrary topic names, labels remain conservatively derived from cluster content rather than pretending to generate human-quality categories or using a keyword taxonomy.

Area development is deterministic: `45% × average memory strength + 25% × average min(activations, 5)/5 + 20% × min(canonical memory count, 5)/5 + 10% × average non-negative centroid cohesion`. Overall development is the memory-count-weighted mean of area development. It measures internal density and reinforcement, not truth, approval, factual confidence, or knowledge of an entire real-world subject. Reorganization only recomputes derived groups and never deletes or rewrites canonical memories.

Neuron participation is derived from each memory's persisted `neuronIds`, which originate from the Brain Engine's deterministic synapse route. A neuron's memory count includes only records whose route contains that neuron. Reinforcement is the average strength of those memories; activity is derived from their activation total; and area participation is the share of that neuron's participating memories in each derived area. No fixed neuron roles are assigned, and the five-neuron/four-synapse topology remains unchanged.

## M3.3.1–M3.3.2 area identity and neural specialization

M3.3.2 replaces one-pass centroid attraction with deterministic two-phase complete-link clustering. Phase one computes each canonical-memory embedding cosine once and orders eligible pair edges by score plus a stable ID tie-breaker. Phase two merges two areas only when **every** cross-area memory pair remains at or above the unchanged `0.62` broad-area threshold, and an area is capped at 12 memories. A→B and B→C can therefore no longer merge A, B, and C when A→C is weak. Singletons are valid derived areas. The input set is sorted by canonical memory ID, making membership independent of caller ordering.

Area IDs remain deterministic hashes of sorted canonical memory IDs. For coherent multi-memory areas (`>= 0.75` centroid cohesion), the display identity is a maximum-five-word excerpt from the most semantically central canonical memory. This is a bounded, truthful source excerpt—not a generated topic name. Singletons, low-cohesion areas, and areas with no displayable content use `Emerging Knowledge NN`. Each area exposes `labelSource`, `labelConfidence`, and `labelReason`. There is no stopword list, taxonomy, pathway mapping, keyword classifier, or external label generator.

New canonical memories retain deterministic routing, but raw-text hashing is now only the fallback. The Brain Engine derives the input's prospective knowledge area from its persisted embedding. If that area already has memories, it selects the most frequently participating existing synapse, breaking ties by canonical synapse order. This gives semantically continuous memories overlapping neural participation without fixed topic-to-neuron roles. A new area continues to use the deterministic text-hash route. Existing memory routes are never rewritten.

A neuron becomes `EMERGING_SPECIALIZATION` only when it participates in at least three canonical memories and one derived area accounts for at least 60% of those memories. Otherwise it remains `UNSPECIALIZED`. Its profile reports local memory IDs/count, activation total, average strength, connected route participation, per-area shares, dominant share, and primary area. Knowledge areas also expose participating neuron/synapse IDs. All calculations are derived and read-only; no database migration is required.

Knowledge clustering performs `O(N²)` cheap cosine calculations and no NLI, paraphrase, STS, or new model inference. Pair values are cached for the derivation pass; representative and audit evidence reuse them. Complete-link merges are capped at 12 memories per displayed area. This is suitable for the current local memory scale while keeping expensive semantic-model work out of rendering. `knowledgeAreaAudit()` exposes per-memory centroid/representative similarities, complete-link consistency, assignment reason, area membership, label provenance, progress, and neural participation without mutating state.

## M3.3.3 knowledge-relation evidence

Production knowledge grouping remains exactly M3.3.2. The development-only knowledge-relation layer reuses the already loaded MiniLM, DeBERTa NLI, paraphrase MiniLM, and TinyBERT STS adapters, including their per-session queues and copied outputs. `inspectKnowledgeRelation(left, right)` reports embedding cosine, forward/reverse NLI distributions, mutual entailment, asymmetry, maximum contradiction/neutral evidence, paraphrase similarity, STS score, and whether M3.3.2 would consider the pair embedding-eligible.

`runKnowledgeRelationMatrix()` runs a fixed 70-pair diagnostic matrix: all 36 pairs from the real nine-memory corpus, 15 within-subject generalization pairs, 10 cross-subject generalization pairs, five hard negatives with parallel sentence structure, and four same-subject pairs with different wording. Expected labels are evaluation metadata only and never enter inference or production decisions.

The shadow classifier is intentionally conservative and non-authoritative. It labels `SAME_AREA` only when the production embedding gate and both existing supporting-similarity confidence bands agree without dominant NLI contradiction; it labels `DIFFERENT_AREA` only when the embedding gate and both supporting models are all weak. Contradiction alone does not exclude a topic because opposing propositions can share a knowledge subject. Every mixed or contradictory evidence pattern remains `UNCERTAIN`. These gates are an evidence-collection hypothesis using existing confidence bands, not a promoted area classifier.

`simulateKnowledgeAreas()` copies canonical records in memory, retrieves at most three neighbors per memory, evaluates at most 24 unique candidate pairs, and requires complete-link `SAME_AREA` evidence for hypothetical merges. It returns production areas, shadow areas, allowed/blocked merges, and uncertain pair evidence with `persistence: "NONE"`. It does not touch IndexedDB, routes, UI, specialization, or canonical state. Real-browser matrix results are required before any promotion; mocked tests establish isolation and mechanics only.
