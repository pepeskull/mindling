# Minimal neural UI and bounded autonomous memory evolution

Base: main `6e0fb7a`, including merged PRs #115–#118. Development uses only local
fixtures and mocked inference. No production data, paid model requests, live web
retrieval, screenshots, dependency installation or deployment were used.

## Audit: existing behavior and actual gaps

The graph projection uses the full canonical `content` as its internal label.
The navigation buttons, tooltips, selected-node captions and default inspector
rendered that same string, including generated source-observation prefixes.
The task inspector directly rendered task diagnostics, plans, source links and
manual correction controls. Neither issue requires editing stored knowledge.

The research pipeline already validates exact cited report passages, source IDs,
dates, hashes, signed checkpoints, request correlation and permissions. It saves
structured category/topic metadata and canonical research records. PR #118's
manual no-op correction protection and shared semantic classification remain.

Research integration previously reused a memory only when its research quote
hash matched. It did not collect additional supporting attribution. Its native
conflict checks saw prefixed canonical content; they could reject a candidate,
but did not retain a useful conflict record or authorize a supported successor.
This change adds local relationship handling at the **existing integration
stage**, after validated evidence has been received and persisted.

## Normal presentation

- Browse, connected memories, area/topic navigation and retained-task links use
  shared `memoryLabel()` / `memoryButton()` projections: topic, canonical area,
  and current/historical state. Missing or provenance-looking metadata produces
  a neutral label; claim text is never mined or truncated to invent a title.
- Canvas memory captions and hover text use those semantic labels. The graph
  topology, renderer, layout, signals, zoom, panning and selection are unchanged.
- The default inspector shows title, area, current/historical state, strength,
  activations and connected memories. Raw content, source strings, contained
  paragraphs, value-history text and manual correction controls are absent.
- Learning tasks show subject, type, real status/progress, current newly retained
  memory count, cited-source count and a brief message. Duplicates do not inflate
  the new-memory count. Paused/failed work never becomes visually completed.
- Technical diagnostics are not discarded or rewritten. They remain in saved
  tasks and the explicitly opened **Memory maintenance** dialog. That separate
  interface retains source/history inspection, existing administrative correction
  and retained-source deletion controls, plus a local JSON export of memory,
  category and task records. The export excludes identity/key records and warns
  that memory content can be private. No destructive bulk-deletion tool is added.
- Native buttons retain keyboard selection and pressed state. Compact entries
  have explicit accessible names; the modal has a name, native focus handling,
  Escape/Close and bounded internal scrolling. New styles use the existing glass
  gradient, typography, colors and borders without adding or inheriting shadows.

## What autonomous maintenance now does

`memory-evolution.js` is shared by main and Preview. It performs no network access,
inference, scheduling, migration or database opening. Integration still runs in
the existing permission-fenced IndexedDB transaction.

1. **Exact presentation-equivalent knowledge:** compare the editable claim,
   removing only a prefix corroborated by stored source metadata. Reuse the
   canonical ID; keep existing source/verification fields intact. Same text with
   a different supported as-of date is an unresolved temporal context, not a
   silently reinforced old current fact.
2. **Supporting evidence:** retain the new exact quote/hash, source URL/hash,
   observation/validity time, task, report metadata and limitations separately
   from the original attribution. Deduplicate by URL/source hash/quote hash.
   New domain groups with no material limitations can add the existing +0.05
   strength increment (capped at 1) and one activation. Repeated or same-group
   citations cannot farm strength. No XP, new canonical fact or specialization
   evidence is generated by reinforcement. Qualified support stays qualified.
3. **Complementary knowledge:** use the existing native safety/relationship
   checks over a read-only view of editable claims, then the existing canonical
   creation pipeline. Retain legitimate relationships and reciprocal links.
   An uncertain paraphrase is not guessed to be either new or equivalent.
4. **Conflicts:** attach bounded unresolved evidence to the current record's
   existing contradiction field, where cognitive retrieval can see it. Preserve
   the incumbent. Source/task records retain the rejected or qualified proposal;
   the task is honestly blocked if nothing can be integrated.
5. **Evidence-supported successors:** a deliberately restricted, deterministic
   policy can authorize a new source-attributed version. It does not implement
   general semantic fact correction.

### Automatic successor eligibility

All of these conditions must hold:

- One current incumbent, identical single-proposition English wording except
  one integer count/measurement, and identical meaningful category and topic.
  Units, subject, punctuation and qualifiers must match. Negation, multi-number
  or multi-sentence text, obvious date/year/current-standings expressions and
  arbitrary semantic resemblance do not qualify.
- Both validity dates are null, the task is not time-sensitive, and the original
  is not independently marked verified.
- At least two newly cited domain groups support the **same exact replacement**,
  with more groups than support the incumbent. Supporting observations must be
  newer than the incumbent's evidence. Incumbent domains cannot vote again as
  new corroboration.
- No material limitations, third conflicting value, incompatible metadata or
  unrelated unresolved conflict. The policy does not silently drop uncertainty.
  Possible competing quantitative paraphrases in other current records also
  veto replacement; similarity can block a mutation but never authorize one.

Domain grouping conservatively uses the final two hostname components, so
siblings are grouped together and shared suffixes such as `co.uk` undercount.
It is not a public-suffix/ownership registry and **does not prove source
independence or factual truth**. Hosted citations still refer to model-generated
source-supported summaries, not independently verified raw page quotations.
The successor retains `tool-cited-unverified-synthesis` status.

The canonical reducer independently rechecks eligibility and the existing task
authorization. Only then may its read-only conflict context exclude the exact
incumbent being replaced. The source-backed record is created using the existing
pipeline; the original receives a historical/version link only after successful
creation. Original content and source metadata survive. The successor has its
own attribution and supporting evidence, inherits valid associations and reuses
neural IDs. Its provenance says `evidence-supported-version`. User claims are
never relabelled as independently verified.

There are at most six support and six conflict entries per memory. Capacity
failures retain existing evidence and report fixed diagnostic codes; they do not
evict uncertainty to authorize replacement. A task's existing receipt/source
records remain available even if per-memory evidence is at capacity.

## Boundaries and compatibility

No acquisition/evaluation schema, model/provider, inference/search budget, signed
checkpoint, receipt validation, permission, origin/onboarding, neural renderer,
IndexedDB schema or existing record migration changes are introduced.

Maintenance consumes already accepted evidence during authorized research. It
does not issue additional searches/completions, force retries of unresolved
conflicts, or create a separate background loop. Existing three/day and ten-minute
automatic scheduling limits remain. New knowledge/successors remain subject to
the existing three-accepted-memory ceiling and 1,000-record capacity. Autonomous
work still awards 0 XP and costs 0 Energy; explicitly initiated research keeps its
existing single activity charge. No-op administrative correction remains free.

Existing records need no migration. Broad semantic changes, ambiguous paraphrases,
time-sensitive corrections and qualified/conflicting evidence remain unresolved
unless the existing mechanisms can safely establish a distinct supported fact.
This implementation is not a general truth adjudicator. It may miss equivalent
wording; it does not silently merge uncertain claims.

## Verification

The local end-to-end Chromium fixture performs three automatic tasks separated by
a synthetic clock that respects the real cooldown/daily guards: retain an initial
claim, retain one conflicting source without replacing it, then integrate a
second corroborating source into a successor. It subsequently checks repetition
and complementary knowledge, real handlers/validation, source history, exact
hashes, graph/identity/origin integrity, budgets and Energy/XP. It then opens the
actual `/` and `?stage-preview=1` interfaces, tests keyboard/history navigation,
minimal progress (including a paused 71% task), maintenance/export, absence of
shadows, complete persisted data, reload and store isolation. All report text and
source URLs are explicit authored test fixtures, not live research evidence.

Results: 18 new Node tests pass; focused new/existing coverage is **83/83**.
Full `node --test tests/*.test.mjs`: **358 pass / 22 fail (380 total)**.
The same full command in a separate unchanged-main worktree:
**340 pass / 22 fail (362 total)**, with exactly the same 22 failing test names.
There are no newly failing tests. The existing failures include obsolete XP
expectations, old decision/evidence fixtures, evolution timing and a read-only
projection assertion.

Ten Chromium scripts pass: the new minimal/evolution end-to-end script,
autonomous integration, source evaluation, limitation recovery, live-research
diagnostics, administrative corrections, analysis-502 recovery, successful-receipt
recovery, actual-URL shared Teach parity and Teach/Deep rollback/retry. Changed
source syntax and Git whitespace checks pass. Diagnostic browser regressions use `renderTaskDiagnostics`
after that view moved out of the normal inspector. The old standalone M3 browser
script contains pre-existing obsolete controls and is not claimed as validated.

## Production verification after deployment

1. Use an existing identity; record memory IDs, hashes, labels, graph, Energy/XP
   and Origin DNA before inspection. Do not reset data.
2. Check Browse/Connected/area/topic/task links and node tooltips: concise metadata
   only, with keyboard selection and historical/current state intact.
3. Select a memory: title, area, strength, activations and connections; no generated
   source prefixes, raw paragraphs/URLs or manual correction controls.
4. Check completed, paused/interrupted and failed task presentation against the
   stored task diagnostics. Unknown work must retain its genuine partial progress.
5. Open maintenance explicitly. Confirm full originals, citations/hashes and
   history remain available, export is local, and existing recovery/removal
   controls work without reintroducing them into the neural inspector.
6. With separately authorized real inference, check duplicate/support/complement
   handling in an ordinary research task. Confirm no extra tool/model requests.
7. Review any eligible numeric successor's two new evidence groups, exact wording,
   metadata, absence of qualifications and original lineage. Insufficient or
   ambiguous evidence must preserve the incumbent. Never interpret a successor
   as independent factual verification.
8. Reload both environments; verify state isolation, original provenance,
   unchanged accounting and no duplicate versions/evidence.

Local mocked end-to-end correction is verified for the narrow policy above.
Successful autonomous correction using live production sources is **not** claimed.
